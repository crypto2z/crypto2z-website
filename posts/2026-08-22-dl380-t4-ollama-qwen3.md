## Why I Needed a GPU on My Node

The AI trading agent has been running since early 2026. The original architecture was simple: a 30-minute decision loop that called Ollama for local inference, Ollama passed the heavy lifting to Phi-3 Mini, and Claude handled final validation before any trade executed.

It worked. But it was slow. And the DL360 Gen10 it was running on — dual Xeon Gold 6230R, 128GB RAM — was doing inference entirely on CPU. With 104 threads you'd think that would be fast enough. It wasn't.

A typical inference call on a complex market prompt was taking 45-90 seconds. When your decision loop runs every 30 minutes, waiting 90 seconds for a local model to think isn't catastrophic. But I'd been watching the model output quality and noticing that longer, richer prompts were getting truncated because the CPU inference was timing out before completing the full context. The system was self-limiting.

Then Qwen3 8B dropped.

## The Model That Changed the Calculus

Phi-3 Mini was a good starting model — small, fast on CPU, decent reasoning for simple market summaries. But I'd been watching Qwen3 8B benchmarks and the jump in reasoning quality was significant. The problem was size. Qwen3 8B at Q4 quantization is around 5GB. Running that on CPU inference on a server that's simultaneously running Nethermind, Teku, and SSV Node was going to create memory pressure and context-switching hell.

I needed GPU offload. All 37 layers of Qwen3 8B, sitting in VRAM, not competing with anything.

The Tesla T4 was the obvious answer.

## Why the T4

The Tesla T4 is a passive cooling data center GPU — 16GB of GDDR6, 70W TDP, designed to sit in a rack without a fan. That last part matters enormously in a homelab. The DL380 Gen10 already has aggressive active cooling built in. Adding a consumer GPU with its own fan would create airflow conflicts and acoustic nightmares.

The T4 sits at PCIe slot `0000:86:00.0` in the DL380 and the server's existing airflow handles it completely. At idle it barely registers thermally. Under inference load it warms up but stays well within spec.

16GB of VRAM means Qwen3 8B at Q4 fits entirely in GPU memory with room to spare. The entire model offloads to the T4 — 37/37 layers. Zero CPU involvement during inference beyond the request handling.

## The DL360 to DL380 Migration

The GPU install happened alongside a platform migration. The DL360 Gen10 had been the Ethereum node since the Ryzen 5500 desktop outgrew its role. The DL360 served well — dual Xeon Gold 6230R, 128GB RAM — but it had a ceiling.

The DL380 Gen10 is a different machine. Same CPU family but with a critical difference: the DL380 has proper PCIe expansion slots that can handle a full-length GPU. The DL360's slot configuration made the T4 install awkward. The DL380 was built for exactly this kind of expansion.

The migration involved:

**Hardware:** Dual Xeon Gold 6230R carried over, RAM expanded to 256GB, Samsung 990 Pro 4TB NVMe at `/mnt/ethereum` for chain data, HPE 622FLR-SFP28 CNA on a 10G DAC to the TP-Link SG3428XPP-M2 switch, dual 800W Titanium PSUs on a 240V circuit. HPE SPP 2026.05 firmware applied across the board.

**Services:** Every service that was running on the DL360 migrated to `10.13.1.10` on the new network (`192.168.50.x` is fully retired). Nethermind mainnet, Nethermind Hoodi, SSV Node (mainnet and Hoodi), Anchor, MEV-Boost, Grafana, Prometheus, Alertmanager — all moved.

**Network:** The whole homelab moved to `10.13.1.x` addressing during this period. The OPNsense experiment on the Protectli V1410 got reverted back to the ASUS RT-BE90U (WiFi 7 and household UDP video call stability won out over pfSense elegance), but the VLAN architecture plans are still coming.

**AI agent:** The trading agent at `/root/ai-agent/` migrated from DigitalOcean to the DL380 on July 25th. Running it on the same machine as the GPU inference engine made the whole system dramatically faster and eliminated the round-trip latency to a remote droplet.

## Installing the T4 and Setting Up Ollama

The physical install was straightforward — passive card, slot it in, done. The software side took more care.

NVIDIA driver 580.173.02 and CUDA 13.0 on Ubuntu 24.04:

```bash
# Confirm the card is visible
nvidia-smi

# Should show: Tesla T4 | 15360MiB total | 0MiB used
```

Ollama installation and GPU detection happens automatically if the NVIDIA drivers are installed correctly:

```bash
curl -fsSL https://ollama.ai/install.sh | sh
ollama serve &
ollama pull qwen3:8b
```

Running a test inference immediately confirms full offload:

```bash
ollama run qwen3:8b "Summarize the current BTC market structure"
```

In the Ollama logs:

```
llm_load_tensors: offloaded 37/37 layers to GPU
llm_load_tensors: VRAM used: 4891 MiB
```

All 37 layers. No CPU fallback. That's the confirmation you want.

One behavioral detail worth knowing: Ollama unloads models after approximately 5 minutes of idle. If you check `nvidia-smi` between agent calls you'll see 0MiB VRAM usage and "No running processes found." This is normal — not a crash, not a fault. The model reloads on the next inference call in about 2-3 seconds.

If you're running a high-frequency inference loop and can't afford the reload latency, you can keep the model loaded by sending a keepalive ping. For the 30-minute trading agent cycle this isn't an issue.

## The Inference Pipeline: Phi-3 Mini → Qwen3 8B → Claude

The trading agent uses a three-stage pipeline:

**Stage 1 — Phi-3 Mini (fast filter)**
The smallest model in the chain. Gets the raw market data and produces a preliminary signal — bullish, bearish, or neutral, with a confidence score. This runs in under 10 seconds on the T4 and acts as a cheap pre-filter. If Phi-3 Mini says "no clear signal, confidence 35%" the agent doesn't escalate to the larger model.

**Stage 2 — Qwen3 8B (deep analysis)**
Only runs when Phi-3 Mini surfaces a signal worth investigating. Qwen3 8B gets the full prompt — OHLCV data, recent portfolio context, MACD state, the Phi-3 summary — and produces a structured trade recommendation with reasoning.

The quality jump from Phi-3 Mini to Qwen3 8B on this task is significant. Qwen3 handles multi-factor reasoning across correlated assets much better. When BTC is pumping and an altcoin in the portfolio is diverging negatively, Qwen3 8B catches that relationship. Phi-3 Mini often missed it.

**Stage 3 — Claude (validation gate)**
The final check before any trade executes. Claude validates that the recommended trade doesn't violate protected coin rules (ETH, ATOM, SOL, AVAX, POL, XTZ, ADA are blocked from selling via `validate_exit`), checks the NY-restricted blocklist (51+ coins), and confirms the MACD cross condition is met.

The MACD cross requirement came from hard data: a 76-trade post-mortem analysis showed it was the only entry signal that produced statistically positive results. Everything else — RSI, volume spikes, sentiment — added noise without adding edge.

## Performance Numbers

Before T4 (Qwen3 8B on CPU, DL360):
- Inference time: 45-90 seconds per call
- Context completions: frequently truncated on long prompts
- CPU contention with Nethermind during busy blocks: noticeable

After T4 (Qwen3 8B GPU offload, DL380):
- Inference time: 6-12 seconds per call
- Context completions: full — no truncation
- CPU contention: zero — model runs entirely on the T4

The T4 reserves 52 of 104 available CPU threads for Ollama even with full GPU offload. This is configurable via `OLLAMA_NUM_THREAD` if you want to cap it. So far the consensus clients haven't complained, but it's worth monitoring if you add more EL/CL pairs to the same machine.

## Why This Matters Beyond Speed

The performance improvement is real and immediately useful. But the more important thing is what it unlocks architecturally.

Running Qwen3 8B locally means the trading agent's core reasoning loop never touches an external API for its primary inference. Claude is still in the pipeline for validation — and I'm fine with that. Validation is a different kind of task, and Claude's reliability on constraint-checking is worth the external call.

But the market analysis, the signal generation, the "should I even be looking at this trade" question — all of that happens on hardware I own, in a building I can walk into, on a model weight file I can inspect.

That's the same philosophy that drives the Bitcoin node, the Lightning node, the Ethereum node. Not because managed services are bad. Because self-sovereign infrastructure is the point.

The T4 just extended that principle into inference.
